# dsh use · 任务报告归档

> 制度：**每次任务完成后留一份报告**，内容是「任务修改详情 + 当时快照」，为后续扩张这套系统提供基线。
> 定于 2026-11-01（志诚要求）。

## 目录内容

| 文件 | 说明 |
|---|---|
| `_模板_任务报告.md` | 复制它来写新报告 |
| `_索引_任务报告.md` | 本文件，报告总目录 |
| `<日期>_<任务>_任务报告.md` | 单次任务的完整报告 |
| `snapshot-<时间>.json` | 机器可读快照（版本矩阵 / 文件哈希 / 状态），用于日后 diff |

## 报告要点（缺一条就算没写完）

1. **一页摘要** —— 做了什么、结果如何、还差什么
2. **交付物清单** —— 路径 + 大小 + SHA256 前 16 位
3. **逐文件修改详情** —— 新增/修改/删除分类，改前→改后 + 原因；显式写出**本次未触碰**的高风险文件
4. **关键决策记录** —— 含被否决的方案（半年后最想知道的就是“当时为什么不那样”）
5. **实测证据** —— 数据、耗时；**失败也要写全**
6. **环境快照** —— 版本矩阵、profile bundles、配置哈希、缺口清单
7. **Roadmap / 风险 / 复现步骤**

## 为什么这么较真

这套系统（dsh + 插件 + superagent-lite + 定时器）正在**边用边扩张**。
扩张最怕的不是改错，是**记不清当时为什么这么改**。快照 + 决策记录的组合，
让任何一次“后来要不要推翻前面”的判断都有据可查，而不是靠回忆。
