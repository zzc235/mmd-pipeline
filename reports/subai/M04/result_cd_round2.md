   同一条规则只改比例（`--ratio 0.50`）：保持段前一半 `302..567` 20 帧（均值 −5.155 mm、最深 −83.250 @f304），后一半 `568..832` 8 帧（均值 −3.161 mm、最深 −65.647 @f646）。

   四条读法，缺一条就会把话说错：

   - **方向**：`max_depth_m` 越负越深，所以保持段中位 **−1.556 比动画段 −1.324 更深 0.232 mm**（我第一版写「整体不更深」，方向反了）；
   - **不均质**：交接瞬态 53 帧的均值 `−17.316 mm` 是稳态 478 帧 `−2.701 mm` 的 **6.4 倍**，而两者中位只差 0.661 mm（−2.205 vs −1.544）；保持段最深的 6 帧有 **5 帧落在 302..354**。⇒ **「保持段 28 帧 / 最深 −83.250 mm」这种说法把 53 帧瞬态的极端值当成了 531 帧整段的属性**，与「跨域相减」是同一类错（把局部当整体）；
   - **保持段不等于静止**：段内逐帧标准差 10.974 mm（动画段 11.359 mm，同级），且段内 `r(帧号, 深度) = +0.18`（动画段 `+0.02`）——**越往后越浅**，与「定格后刚体先沉降、再趋于稳定」一致。骨骼定格，物理还在跑；
   - **这条规则的稳健性有下限，而且下限是「两级台阶」**：比例不是物理量，真正决定分界的是**哪几帧被圈进瞬态窗口**——`f347`（−81.290 mm）要 46 帧（占段长 8.66%、`round()` 阈值 8.57%）、`f353`（−69.097 mm）要 52 帧（9.79% / 9.70%）。实测三级：**8%** → 稳态仍有 21/28、最深 **−81.290 @f347**；**9%** → 15/28、**−69.097 @f353**；**10%** → 11/28、**−65.647 @f646**。所以「极端值集中在交接」要成立，比例至少 9.70%（取整数即 10%），而 9% 会给出另一组数。引用瞬态占比必须**连比例一起写**。

   所以引用 `C@W2` 的数必须带**段 + 窗口 + 极端值所在帧**三样：全窗 1..832 → `48 / −83.250 @f304`；动画段 1..301 → `20 / −80.417 @f95`；交接瞬态 302..354 → `17 / −83.250 @f304`；稳态保持 355..832 → `11 / −65.647 @f646`。**最深那一帧（f304）落在交接后第 2 帧**，写的时候要明说，别让它冒充「整段的深度」。`C@W1 vs C@W2` 的同域比较取 1..240（都在动画段内），不受影响。
5. **`over_eps` 的含义**：只说明「比该臂首帧深 ≥ 20 mm」，**不说明网格穿入**。胶囊是 PMX 作者给的近似体（`caveats` 里一直写着的那条），胶囊无重叠不能替代网格测量，胶囊有重叠也不等于网格穿模。
6. 本轮**没有**做 `C vs A`（跨尺度不可比），也没有做 `B vs A`（`B` 早按 `D-134` 作废）。三臂之间只做了上面两对。

## 十一、口径裁定（19:42，`D-224`）：这条窗口**永久是 `post_hoc`**，只能作解释

`总控` 对我与 `4号` 这四轮「下限到底是几」的裁定：**算得干净，但这个数不能当口径**。

理由不是我们算错了，而是**那两帧是从数据里挑出来的**——先看到 `f347`/`f353` 让结论翻，才反解出比例。所以用它定义窗口，无论写成帧号、帧数还是百分比（`9.70%` / `9.79%` / `10%`），都是 `post_hoc`；若写进预注册，等于**用数据的结论去规定数据的窗口**，与 `302..351` 是同一个错，只多绕了一层算术。**绕了一层算术的事后窗口比一眼看出来的那种更危险。**

据此改了三处：

1. **§六 第 4 条整段降为解释性描述**：分段表、`8% / 9% / 10%` 的三组数、`9.70% / 9.79%` 全部标 `post_hoc`，只能作解释、不许作判据（§三 已写明可当判据的只有同域 `f1..240` 对比与 `D` 的分布量）。
2. **脚本默认值改成 `post_hoc`**（`--rule-kind` 默认 `post_hoc`，非法值 exit 2），并把 `--boundary-frames` 的输出明确标成「描述」；`segment_ratio` 也不再自称「先于数据可判」。
3. **「对切点稳健」改由 `coordination.comparability.cut_sensitivity()` 算**，本脚本只打印它的判词。同一份数据、比例 `8% / 9% / 10%`，它给的是 **`UNSTABLE`**（`worst_frame_stable=False`，两段极值帧 `f304 / f347 / f353 / f646`）：`prefix` 恒为 `f304`（看着稳），**翻的是 `rest`** —— 这正是只看 `prefix` 会漏掉的那一类。

**判词不受影响**：`JUDGED_NO_CHANGE` 用的是「有没有越判据帧」，而同域比较取 `f1..240`（两臂都在动画段内），`D` 全程在动，都不碰保持段切分。四轮没有白跑，它量清的是「保持段的数有多脆」——**结论是这些数不该进结论句，不是该挑一个更好的比例**。
