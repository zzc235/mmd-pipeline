## 0. 一句话：v2 §4 第 1 条错在哪

v2 写的是：

> 建场产物**不烘**：`mmdpipe/stage.py` 不调用 `bake_all`（全文件仅 `stage.py:1299` 一处**读** `is_baked`）

这句话在**现状**上是对的（代码确实不烘），但在**契约**上是错的：交付契约是 `D-067` 的
**B = 烘焙**，而「不烘」是 `cache_state.py:179` 那条**降级路口径**。我当时把降级路口径当成了契约，
于是把「现状」写成了「应当」。`D-153` 就是这么判的，我接受。

**这类错误的形状**（记在这里，因为它比这一处本身贵）：**拿现状冒充契约**。同一个病在测量侧的样子是
「A 组基准读的是文件里的缓存，不是一次解算」。修法也必须两头对称：

| 侧 | 判据 |
|---|---|
| 契约侧 | 烘不烘是**显式参数**，连同烘焙参数、`pose_source`、`is_baked`/`is_outdated` **随件落盘**，不靠读代码推断 |
| 测量侧 | 一律 `fresh_solve`（清缓存 + 从 `frame_start` 顺序解算）；「姿态可复现」只由**两次独立解算逐位相同**证明 |

这两条就是下面 §1。

## 1. 契约与测量口径（取代 v2 §4，`D-067` / `D-153` / `D-158`）

1. **交付件按契约烘**（`D-067`）。烘焙**不是**读代码推断出来的，是**显式参数**：每份交付件必须随件记
   `bake: {requested, applied, frame_start, frame_end, fps}`、`pose_source`、`is_baked`、`is_outdated`。
   读者不需要打开 `stage.py` 就能知道这是不是烘过的件。
2. **测量一律 `fresh_solve`**：每组各自新进程 → `free_bake_all()` → 回读 `is_baked == false` →
   从 `scene.frame_start` 顺序 `frame_set` 到 `frame_end` → **再读一次** `is_baked`（走完帧之后；
   只看「清之前」不够）。任一为真 ⇒ 该组读数作废、判 `UNMEASURED`。
3. **`cache_replay` 的读数单独命名**（如 `A_cache`），只作「这份文件里的缓存长什么样」，**不进任何比较**。
4. **「姿态可复现」只由「两次独立解算逐位相同」证明**。两次都回放同一份缓存也能给出逐位为 0，
   那是仪器自证，不是可复现性（v2 §5 第 1 条的前提，本节把它升为硬判据）。
5. 每组输出必须自报 `truth_tier`：`fresh_solve` 至多 `T3`；`cache_replay` 一律 `T_DESCRIPTIVE`。

## 2. `D-155` 待决项：交付动画以哪次解算为准（两支都预注册，不替 Human 选）

`D-155` 的实测：同一份旧件，读自带 240 帧缓存 vs 清缓存重解，第 88 帧差 **71.059 mm**、重叠对数差 **18 364 对**
（23 451 vs 41 815），而重解本身两次会话 240/240 复现。⇒ 那份缓存**与我们今天从头解算的不是同一个姿态**，
且来源不可追溯。

**Human 未定之前，本层不开跑。** 无论如何，两支都按下面的写法落盘，不许事后改口径：

| 支 | 内容 | 落盘要求 |
|---|---|---|
| **①（默认，`D-067` 顺推）** | 交付动画以**我们自己 `fresh_solve` 的那次姿态**为准，烘的就是它 | `bake.requested=true`、`pose_source=fresh_solve`、烘焙参数与帧区间、`is_baked` 两处读数 |
| **②（需 Human 明确指定）** | 以旧件缓存里的姿态为准 | 必须同时给出**来源可追溯性**证据（哪次会话、哪份文件、sha256）；给不出 ⇒ 不得作为交付姿态 |

**这一节只在「哪次解算」这一件事上等 Human**；`D-158` 的三条（§1）不等，它们与这一支无关，必须在两种情况下都成立。

## 3. 闸门判据是**恒等式**，不是「两个数相等」（`D-160`）

v2 §3 的 B 组闸门条件沿用，但判法要按今天的读数改正：

| 条件 | 判法 |
|---|---|
| `verdict` | `stage_mask()` 读 `scene["mask_wired"]`（`D-162`：记录写进场景本身），必须 `WIRED` |
| `capped` | `constraints_capped == false` |
| `skipped` | `skipped_count == 0` 且 `skipped == []` |
| 计数 | **`constraints_added + constraints_already_blocked == constraints_needed`**（恒等式） |

**不许把最后一条写成 `added == needed`**：那只在**新建场景**成立（`already = 0`）。
`J_baked` 那种「已挡对 1813 条」的场景里 `already ≠ 0`，两数本来就不相等，拿「相等」当判据会把好场景判红。

**A 组（未接通道）不过闸门是预期**：`stage_mask()` 会读 `PARTIAL` + 无记录，探头读 `UNWIRED`。
这条**必须写进报告**，否则三个月后有人看到 `PARTIAL` 会以为整层没跑通（v2 §3 原样保留）。

4. **`pose_source` / `truth_tier` 升为硬要求**（§1 第 5 条）：v2 只说「必须自报」，没说自报之后怎么用。

**没变的**：1 mm 判据、`下擺_0_*` 逐帧最大位移、两次独立建场（`stage_sha256`/`mask_sha256` 必须相同）、

## 6. 风险与事先的处置

| 把降级路口径又当契约（v2 的病） | §1：烘焙是显式参数、随件落盘；引用契约只引 `D-067` |
