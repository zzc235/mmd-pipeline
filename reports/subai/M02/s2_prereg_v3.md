## 0. 背景与为什么要预注册

原口径「±0.7 rad 限位从未被触及」是拿**模拟量**（下摆骨解算出来的角度）去比一个**给输入定的限位**，
而且在驱动量只有腿 X 峰值 `0.1031 rad` 的场景上量的。两件事都要纠正：

- 当前场景驱动不足（比舞蹈动作小约 20 倍），「未触及」首先说明场景驱动不够；
- `31/31` 个唯一动作里裙骨 X 峰值全为 0 ⇒ **下摆骨从来没有动画输入，只由物理解算驱动**。

## 1. 因变量（两个，必须分开叫）

### 1.1 触及判据用的量：`rot_x`

| 项 | 写死 |
|---|---|
| 刚体集合 | `下擺_0_*` 共 18 根（`下擺_0_0` … `下擺_0_17`），与 PMX 结构筛出的一致 |
| 轴 | **`rot_x`**（与 `limit_ang_x` 同轴的单轴旋转量），**不用合成角 `angle_deg`** |
| 分解顺序 | 四元数 → 欧拉 XYZ，取 `rx`。顺序依赖；跨报告只认这一种 |
| 采样 | 每一帧（不抽帧），帧区间见 §1.3 |
| 聚合 | 18 根骨 × 全部帧取 `max |rot_x|`，**并在报告里写出这个实际数值** |

### 1.2 **此量只用于判「触及 / 部分触及 / 未触及」，不参与判效应量。**

### 1.3 帧区间（v1 的缺陷）

动作 `原神摇` 长 **832 帧**，而当前场景帧范围是 `1–240`。**照 v1 的写法跑，峰值很可能落在被裁掉的后 592 帧**，
然后得出「未触及」——那是**裁剪造成的假阴性**，与 `scanned=0` 伪绿同族。

写死：**`frame_start = 1`，`frame_end = 动作全长`（本动作为 832）**，并在报告里回读实际生效的
`scene.frame_start / frame_end` 与动作 `action.frame_range`，两者不一致即作废本次运行。

### 1.4 自变量（驱动）与它的效力边界

- 场景动作：`kafuka_all/vmd/原神摇_merged.vmd`（sha 写进报告）
- 驱动量代理：腿骨（`足`/`ひざ`/`もも`，**排除 `ＩＫ` 骨**）`rot_x` 峰值
- **代理只用于在 31 个动作里排序选场景，不是效应量，不参与任何判词**
- 已知限制：与当前模型骨名交集 `94/332`（28.3%），缺失的是手指/捩/袖/胸等装饰骨，它们停在静止姿态；
  十一根关键驱动骨（`センター`/`上半身`/`下半身`/`左足`/`右足`/`左ひざ`/`右ひざ`/`左足ＩＫ`/`右足ＩＫ`/`全ての親`/`グルーブ`）全部命中。
  凡说「S2 通过」都必须同时说「装饰骨未驱动」。

## 2. 什么算「触及」

| 判定 | 条件 |
|---|---|
| 触及 | `max |rot_x| ≥ 0.7 rad` |
| 部分触及 | `0.5 ≤ max |rot_x| < 0.7 rad` |
| 未触及 | `max |rot_x| < 0.5 rad` |

阈值 **0.7** 取自当前解算里的 `limit_ang_x` 本身；**0.5** 取自既有实测里「已观察到会咬到」的最高档。
**两者都不是这次挑的。**

## 3. 三种结果的判词（先写死）

| 结果 | 判词 |
|---|---|
| 触及 且效应量 > 1 mm | **S2 通过**：写明骨、帧、量级 |
| 触及 但效应量 ≤ 1 mm | **S2 通过但不重要**：写「限位在该摆幅下不起作用」，M02 不作废 |
| 部分触及 / 未触及（舞蹈也不够） | **S2 = `UNMEASURED`（不是 PASS）**，留在 M08 的 `UNMEASURED` 一节 |

**「测不出来」永远不等于「没有问题」。第三种结果不许改写成「无影响」。**
「部分触及」虽然也归 `UNMEASURED`，但**必须写出 `max |rot_x|` 的实际值**——0.5–0.7 意味着
「限位咬到了但没到限位值」，这个数本身有价值（说明限位在该摆幅下处于边缘），只是不能拿它宣布通过。

## 4. 前提条件（不满足就不跑）

1. 掩码通道已落地，且 `m02_mask_channel_probe.py --expect wired` **退出码 0**；退出码 2 → 不跑，保持 `UNMEASURED`；
2. 该次探头读数（`distinct_patterns` / `separated` 两桶 / `DISABLE_COLLISIONS`）与场景 sha、动作 sha 一起写进报告；
3. 源 `.blend` 前后 sha 一致（只读场景，不覆盖入参）。

## 5. 对照怎么设（A/B）

- **A**：`limit_ang_x = ±0.7 rad`、`use_limit_ang_x = True`
- **B**：`limit_ang_x = ±1.5708 rad`（当前交付值）
- 其余一切不动：同一 `.blend`、同一动作、同一帧区间（§1.3）、同一缓存处置（先 `free_bake_all()` 再顺序重算，不用 `bake_all`）

### 5.1 只改哪些刚体（v1 的缺陷）

**只改 `下擺_0_*` 对应的 18 个刚体**，其余 **306 个一字不动**。报告里给出改动刚体的名单（18 行）与数量 `18`，
以及未被改动刚体的计数 `324 - 18 = 306`。若将来要改全体刚体，**另开一组**，不与本次混跑——
否则 A/B 的差会同时包含「身体刚体限位」与「裙摆限位」两个来源，效应归因不了。

### 5.2 两个进程（v1 的缺陷）

**A 与 B 必须在两个独立进程里各跑一次**（两个新 `blender -b` 进程，各自加载同一条 `.blend`）。
同进程连跑会让缓存串味——`bake_all` 上已经吃过一次「同进程 `is_outdated=false`、重开文件又变 true」。

每次运行必须写进报告的字段：

| 字段 | 说明 |
|---|---|
| 进程 PID | `os.getpid()` |
| `free_bake_all()` 之后的 `point_cache.is_baked` / `is_outdated` | 两值都记 |
| 行为探针 | 冷跳帧 vs 顺序重算逐位相等**才允许继续**；不相等即作废本次 |

### 5.3 C 组：仪器正控（**不进任何判词**）

A 与 B 若给出 0 差异，有两种解释分不开：① 限位真的不起作用；② **这套量法根本看不见限位效应**。
所以必须配一个人为改造的对照，而且我们**已经有一个能看见的例子**：`±0.001` vs `±1.5708` 曾给出 **5.5 mm**。

| 项 | 写死 |
|---|---|
| 设置 | `limit_ang_x = ±0.001 rad`、`use_limit_ang_x = True` |
| 刚体 | 同 §5.1 的那 18 根，其余 306 不动 |
| 动作 | 同 A/B（`原神摇_merged.vmd`） |
| 帧区间 | **允许只跑 `1–240`**：本组是仪器正控、不参与 S2 判词，故不受 §1.3 的 832 帧约束（这是 §1.3 的唯一例外，且仅适用于本组） |
| 进程 | 同 §5.2：独立新进程，记 PID、`free_bake_all()` 后两标志、行为探针 |
| 上报 | 一行：**`C(±0.001) vs B = X mm`** |

**C 的作用与判据**：

- C **不参与 §3 任何一行**，它的读数不改变 S2 的 PASS / UNMEASURED；
- `X ≤ 1 mm` ⇒ **仪器有问题，本次 A/B 作废**（不是「限位不起作用」）；
- `1 mm < X < 5.5 mm` ⇒ 可用，但必须同时写出与 `5.5 mm` 这个既有读数的差异并说明为什么变小，不许默认接受；
- `X ≥ 5.5 mm` ⇒ 仪器有效，A/B 的差值可以被解读。

## 6. 效应量的量（与 §1 分开）

### 6.1 用什么

18 根 `下擺_0_*` 刚体在全部帧上的**位置差**（A 与 B 同一帧同一刚体的欧氏距离），
报逐帧最大值、出现帧、以及 >1e-6 m 的刚体数。

### 6.2 **此量只用于判「效应量 > 1 mm」，不参与判触及。**

### 6.3 1 mm 判据的来源

`1 mm` 来自**此前预注册的验收判据**（S2 的验收口径，早于本文件），**不是这次挑的**。
若将来要改成别的值，必须另出预注册并说明理由，不许在报告里就地调整。

## 7. 可能的偏差与事先的处置

| 风险 | 处置 |
|---|---|
| 动作与模型骨名覆盖不足导致裙摆没被激励 | 先看 §1 `max |rot_x|`；不到 0.5 就按 §3 第三种结果处理，**不换模型** |
| 解算发散（此前 1 cm 位移能放大到 1.6 m） | 报绝对位移时同时报「是否发散」；发散只作连通性证据、不作效应量 |
| 缓存陈旧（今日已知缺陷） | 一律先 `free_bake_all()`，用 `m02_cache_gate.py` 行为探针确认，退出码写进报告 |
| 帧区间被截断（v1 缺陷，见 §1.3） | 回读 `scene.frame_end` 与 `action.frame_range`，不一致即作废 |
| 单进程串味（v1 缺陷，见 §5.2） | A/B 各自新进程，记 PID 与缓存两标志 |
| 误改全体刚体（v1 缺陷，见 §5.1） | 只改 18 根，报告给名单与 `306` 未改计数 |
| 仪器看不见限位效应（A/B 差 0 的另一种解释，见 §5.3） | C 组 `±0.001` 必须给出 `X > 1 mm`；否则本次 A/B **作废**，不写成「限位不起作用」 |
