## 0. v1 之后发生的三件事（都是实测，不是我改主意）

1. **交付件还没出来，且第一次尝试被掐**（`D-144`）：`delivery_v1.blend` 由
   `m02_build_delivery.py` 按 main 树重建，此前那次重建导入的是我分支的代码（`D-147`），通道段根本不存在。
   所以 v1 §4 的「A 组 = 保持场景构建时的原样」在实现上必须落成**两次独立建场**，见 §2。
2. **mask 通道的判据升级**（`D-145`）：`WIRED` 现在要求四条同时成立（位型≥2 / 回读零失败 /
   每对「该分」都被分开 / 无 cap 无 skipped）。这一条改变不了 A 组的定义，但改变了**闸门能用在哪一组**，
   见 §3。4号 还把建场记录写进场景自身（`scene["mask_wired"]`），因此「没记录」不再等于「没问题」。
3. **烘焙缓存会把「改了什么」整个遮掉**（2号 2026-11-16 15:21 的 A0 v1）：`point_cache.is_baked=True`
   时 `frame_set` 顺序走帧读的是**旧解算的回放**，240/240 帧逐位相同，`max_abs_delta_m = 0.0`。
   那个 0 会被读成「通道没影响」，而真相是「谁都没动」。v1 §4 有一句 `free_bake_all()`，
   **但没说清「清完之后还要再看一次」**，也没要求读数自报来源。见 §4。
   补充（2号 15:25 的 A0 v2，已更正他 15:21 的结论）：清缓存之后仪器**是有效的**
   （tier=3，239/240 帧 A0 更深，中位 |Δ| 10.878 mm），所以「看不见」是缓存造的假象，不是仪器瞎。
   更要紧的一条：**同一份旧场景的缓存姿态与从头重解的姿态不是同一个东西**——
   第 88 帧差 **71.059 mm**、重叠对数 23451 vs 41815（差 18364 对），而重解本身两次独立会话 240/240 复现。
   ⇒ **场景结构可重建 ≠ 姿态可重建**；所以本层的两组必须是**新建、且都从 `frame_start` 顺序重解**的产物，
   任何「读旧缓存当基线」的写法都不许进这一层。

## 1. 因变量：与 v1 §2 完全一致，不改

`下擺_0_*` 刚体在全部帧上的逐帧最大位置欧氏距离，单位 m，6 位小数；旋转量不参与本层判词。
判词阈值仍是 **1 mm**（v1 §3 原样，不重定）。

## 2. 两组怎么造：**两次独立建场**，不是「同一个场景里改位」

| 组 | 建场命令 | 掩码通道 | 判据用途 |
|---|---|---|---|
| **A（未接）** | `preset` 副本里 `physics.apply_collision_masks: false` | 不接 | 与 B 比出位移差 |
| **B（接通）** | 原 `presets/feiying.json`（默认 `true`） | 接 | 同时是闸门对象 |

两次都走 `m02_build_delivery.py`，各自落一份 `build_identity_*.json`（记录 `stage_sha256` / `mask_sha256` /
`v3_sha256` / `argv`）。**两次的 `stage_sha256` 与 `mask_sha256` 必须相同**，不同则本次作废
（两组的差必须是「通道开关」，不是「换了一版代码」）。

为什么不用「同一个场景里把位清零」：v1 §4 已经说过——位全清是「谁都不碰」，与「掩码未接线」不是同一件事；
而且在已建场的场景上改位，前态里已经有通道建出来的约束，改位等于改两个东西。

## 3. 闸门只吃 B 组，且必须两个实现同时点头（`D-145`）

| 对象 | 要求 |
|---|---|
| **B** | ① `m02_mask_channel_probe.py --expect wired` **退出码 0**；② `stage.stage_mask(root).verdict == "WIRED"` 且 `constraints_capped == false` 且 `skipped_count == 0` |
| **A** | **不许**过闸门。A 的定义就是「通道没接」⇒ 探头会读 `UNWIRED`、`stage_mask` 会读 `PARTIAL`+`no_wired_record`，**这是预期**，不是失败 |
| 任一组的读数缺失 | 本层判 `UNMEASURED`，不出位移数 |

**A 组不过闸门这件事必须写进报告**，否则三个月后有人看到 A 组 `PARTIAL`，会以为整层没跑通。

## 4. 缓存处置（写死，任一不满足即作废）

1. 建场产物**不烘**：`mmdpipe/stage.py` 不调用 `bake_all`（全文件仅 `stage.py:1299` 一处**读** `is_baked`），
   但我**不许据此推断**，必须回读：`point_cache.is_baked == false`；
2. 每组**独立进程**，从 `scene.frame_start` 顺序 `frame_set` 到 `frame_end`；
3. **解算之后再读一次** `is_baked`（只看「清之前」不够：走完一遍帧仍可能被场景设置重新烘上）；
   解算后为真 ⇒ 该组读数作废，判 `UNMEASURED`；
4. 输出必须自报 `pose_source`：`fresh_solve` 才可引用；`cache_replay` 一律不得引用。
   实现已在 `m02_s8_ab.py`（`point_cache_before` / `after_free_bake` / `after_step` + `pose_source` +
   `refused_replay`，后两者为今日新增；**该文件的新增部分尚未在真场景上跑过**，跑通后随下一笔报告）。

## 5. 正控：v1 §5 两条不变，但第 1 条的判法必须带缓存前提

1. **重复性正控**：A 组跑两次，逐帧位移逐位为 0。**前提是两次都是 `fresh_solve`**——
   两次都回放同一个缓存也能给出「逐位为 0」，那是仪器自证，不是可复现性；
2. **灵敏度正控**：A 的副本上把全部刚体 `kinematic` 置真，逐帧位移必须远大于 1 mm
   （历史读数 1.69 m 量级，324 刚体旧场景）。给不出 > 1 mm ⇒ 本层 `UNMEASURED`。

## 6. 报告必须包含（在 v1 §7 之外新增）

1. 两份 `build_identity_*.json` 的路径与 `stage_sha256` / `mask_sha256`（并证明两者相同）；
2. B 组两条闸门的**各自**退出码 / 判词 / `verdict_reasons`；
3. A 组读数（`UNWIRED` / `PARTIAL` + 理由）——标明「预期」；
4. 每组的 `pose_source`、`point_cache_before` / `after_free_bake` / `after_step` 三个状态；
5. v1 §7 原有的六项照旧（逐帧最大位移 + 出现帧 + 超 1e-6 的刚体数、三组读数、文件 sha、
   `apply_collision_masks()` 返回字段、探头退出码）。

## 7. 不做什么（在 v1 §8 之外新增）

- **不在 A 组上跑 `--expect wired`**，也不把 A 组的 `PARTIAL` 当失败；
- **不在同一份产物上做两组**（必须两次独立建场，见 §2）；
- **不把「两次逐位相同」当可复现性**，除非两次都自报 `fresh_solve`；
- 不在 B 组闸门任一条件未满足时开跑——那时的位移数不知道归给哪个解算。
