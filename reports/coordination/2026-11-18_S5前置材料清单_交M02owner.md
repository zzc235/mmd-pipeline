## spec 必须通过的前置闸门（preflight 五道，缺一即 BLOCKED）

owner 提供的 spec 会被 `coordination/preflight.py::check()` 逐项判，五道全过才 READY：

| 闸 | 字段 | 判据 |
|---|---|---|
| provenance | `provenance` + `external_roots` | 引用的每个 source script / blend / preset / plan 必须真实存在且通过来源核真（外部根另列） |
| capacity | `needs` / `cap` | 两者都要有且是数字；`needs <= cap`，否则 `CAP_UNMET` |
| skipped | `skipped` | 未声明按 0；非 0 即 `GATE_FAILED`（跳过的活不算做完） |
| lease | `lease` / `expect_owner` / `lease_dir` | `lease=false` 时跳过；否则要持锁、心跳新鲜、持锁人含期望 owner |
| outputs | `outputs` + `run_id` | 目标已存在时必须由新 run_id 认领或有 overwrite 裁决，否则 `OWNERSHIP_VIOLATION` |

补充：
- `expect_owner` 应为 `模块负责1|A1`（若 owner 另有指定以其为准）。
- dry-run 本身**不占锁、不产文件、不写 board**；但 spec 里声明的 lease 状态仍会被读来判闸，所以 lease 那道要按真实情况填。
