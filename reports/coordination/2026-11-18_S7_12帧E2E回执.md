### 2.2 缺陷：final 目录内 state 陈旧（RETURN_FIX 的根因）

| 文件 | ok | finished_at | final 段 | mtime |
|---|---|---|---|---|
| 根 `pipeline_state.json` | True | 2026-11-18 15:13:12 | 有 | 1794985992.873 |
| `work/<run_id>/pipeline_state.json` | True | 2026-11-18 15:13:12 | 有 | 1794985992.874 |
| `final/<run_id>/pipeline_state.json` | **False** | **None** | **无** | 1794985992.819（早 54ms） |

根因（`mmdpipe/runner.py` 收尾，A4 与 integration 同 sha `cf13d3fd…`）：

```
state["ok"] = not state["blocked_by"]
if state["ok"] and paths["final"]:
    landed = layout_mod.promote(out_dir, paths["final"])
    shutil.copy2(state_path, os.path.join(paths["final"], "pipeline_state.json"))   # ← 此刻 state_path 磁盘上还是旧内容
    state["final"] = {"dir": ..., "files": landed}
_write_state(state_path, state, run_state_path)   # ← 最终正确版只写到 root/work，没再同步进 final
```

`copy2` 发生在最终 `_write_state` 之前，复制的是上一次落盘的旧 state（ok=False/finished=None）。最终版虽写回 root 与 work，但 final 里的那份已经陈旧。

**影响**：成片、帧数、run_id、输入只读都正确；坏的是 final 目录内的**证据账**——它自己声称"没通过、无 final 段"，与同目录的成功成片矛盾。这正是本流水线最在意的"状态载体不许说谎"。

**修复方向（本轮不改代码，待单独授权）**：把 `shutil.copy2(state_path, final/pipeline_state.json)` 挪到最终 `_write_state(...)` 之后；或直接在最终 `_write_state` 里把 mirror 目标加上 final 路径。改后需复跑：相关 state/layout 单测 + 三环境全量 + 一次 E2E 正例确认 final state 的 ok/finished/final 段与 root 一致。
