## 2. 本轮修改

### 2.1 `coordination/run_task.py`

生产顺序改为：

```text
只读任务/参数预检
→ worktree/base/head/dirty 校验
→ preflight
→ 原子 claim/start + 登记 RUN_ISSUED
→ 执行命令，同时续 board 任务/资源租约
→ 证据提交；失败则 RUN_FAILED + blocked
```

具体修复：

1. dry-run 使用 `Board(readonly=True)`，不再 claim/start、发号或占资源。
2. 真实执行把 worktree 与 preflight 放在 claim/start 之前，开工前拒绝保持原状态。
3. 候选 run_id 先用于展开 preflight 路径，但不写事件；真实执行前才登记。
4. 非 none 资源 + `--no-lock` 返回 `RUN_USAGE`，且在 claim 前拒绝。
5. 非零命令退出保留原 rc，调用 `Board.fail_run()`。
6. 执行期间启动 board 心跳，不再拿文件锁心跳冒充 board 租约心跳。
7. `allow_dirty=True` 只放宽执行限制，返回的 `dirty` 仍按真实 Git 状态填写。

### 2.2 `coordination/board.py`

- `new_run_id()`：生成候选号但不写库。
- `issue_run_id(task_id, run_id=None)`：真实执行前登记候选号。
- `heartbeat()`：同事务续 `tasks.lease_until` 与 `resources.lease_until`。
- `fail_run()`：仅允许 claimed/running → blocked；清 owner、释放资源、追加 `RUN_FAILED`。

### 2.3 `coordination/sync_board.py`

`check/verify` 新增真实对账：

- 任务在 JSON 中存在但 board 缺失 ⇒ `tasks` 冲突；
- board 资源与 `task_graph.json` 不一致 ⇒ `resource` 冲突；
- 实际依赖与声明图不一致 ⇒ `deps` 冲突，列出 missing/extra；
- 有冲突时返回 `PHASE_B_CHECK_CONFLICT`，CLI exit 3；
- 任务行的 `board` 现在显示真实运行状态，`sync_target` 单独表示 JSON 映射目标；
- 不强迫 ready/running 与 legacy PARTIAL 相等，避免误杀正常调度状态。

- 更新 `coordination/ARCHITECTURE_V2.md` 的真实执行顺序与失败语义。
