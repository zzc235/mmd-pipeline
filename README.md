# mmdpipe · MMD 角色 + VMD 动作 → 成片

只做一件事：**把「PMX + VMD → 成片」这条链路稳定地复现出来**，并在每一步能失败的地方设断言。

不含 GUI 视窗、不含 IK/FK 控制层、不含场景/音乐/运镜扩展。

## 装成 Blender 插件

`dist/mmd_pipeline-<version>.zip` 就是成品扩展，内含本库与预设。

```bash
blender --command extension install-file -r user_default -e dist/mmd_pipeline-1.1.0.zip
```

或图形界面：`编辑 → 偏好设置 → 获取扩展 → 右上角下拉 → 从磁盘安装`。

装好后在 3D 视图侧栏出现 **MMD Pipeline** 面板；也能直接调：

```python
bpy.ops.mmd_pipeline.render(
    pmx="模型.pmx", vmd="动作.vmd",
    out_dir="输出目录", frames=360, fps="30",
    physics_policy="strict", chain_mode="splice",
)
```

- 面板里的「渲染成片」按钮与命令行**完全等价**，走的是同一个 `runner.run()`。
- 重新打包：`python build_addon.py`（单一来源，库只有工作区那一份）。

## 外观路线（换模型不再崩）

| `look.route` | 用于 | 做什么 |
|---|---|---|
| `hsr` | 星铁角色 | 材质 / SDF / 描边 / 光照向量 / 后期处理 |
| `native` | 其他模型（原神、通用 MMD） | 保留自带 MMD 材质 + 三点光 |
| `auto`（默认） | 不确定时 | 先试 hsr，材质失败就回退 native 并记 WARN |

`auto` 回退时会写 `route_effective=native`，流程不中断。

## 多段动作：两条路

| `--chain-mode` | 做什么 | 代价 | 什么时候用 |
|---|---|---|---|
| `splice` | 字节级拼接，只改帧号 | 4.7 MB / 665 曲线 / 1.8 s 导入 | 同骨架、硬切、要无损 |
| `nla` | 导入成两条 NLA 轨道 → 交叉淡化 → `nla.bake` → 官方 `export_vmd` | 22 MB / 1722 曲线 / 15 s 导入 | 需要过渡、需要改姿态 |

`nla` 路线全部用现成能力：`use_nla=True` 分层、`strip.blend_in` 淡化、`bpy.ops.nla.bake` 烘焙、`mmd_tools.export_vmd` 导出。

**根链对齐**（仅 `nla`）：烘焙前测 A 末 / B 首的**世界**根位置，按"根位移 / 脚位移"比例判定是站位差还是姿态差，
需要时直接改 B 的 action（只影响 B 的条带）。

```bash
--align auto    # 默认：按测量判定
--align none    # 不动（确认是刻意的换场）
--align match   # 强制对齐
```
两个必须注意的点：下层条带 `HOLD`、上层 `NOTHING`（否则会上层把下层整段覆盖）；要淡化则把上层条带向前延伸 gap 帧并同步 `action_frame_start/end`。

## 两层

| 层 | 模块 | 依赖 | 能回答什么 |
|---|---|---|---|
| 纯 Python | `pmx` `vmd` `match` `preset` `report` `preflight` `layout` `statefile` | 无 | 这个模型有没有物理、掩码语义对不对、这个 VMD 套得上吗、产物落在哪、旧 state 能不能读 |
| Blender | `stage` `runner` | bpy | 建链、接动作、材质、取景、渲染、验收 |

## 用法

预检（不开 Blender，几秒钟）：

```bash
python -m mmdpipe.preflight 模型.pmx 动作.vmd --json 报告.json
```

完整复现：

```bash
blender -b -P run_pipeline.py -- \
  --pmx "模型.pmx" --vmd "动作.vmd" \
  --out 输出目录 --frames 360 \
  --preset presets/feiying.json \
  [--probe] [--force]
```

产物默认分两处（`--layout isolated`）：中间产物在 `work/<run_id>/`（`frames/s_XXXX.png`、`scene.blend`、`preflight.json`），**只有全流程通过才落** `final/<run_id>/`（`result.mp4`、`contact_sheet.png`、`camera.json`、`scene.blend`、`pipeline_state.json`）。`pipeline_state.json` 留在 `--out` 根目录，记的是"最近一次运行"。想回到旧的平铺行为加 `--layout legacy`。

验收先看 `final/<run_id>/contact_sheet.png`（12 帧联络表）；没通过时 `final/` 是空的，产物留在 `work/` 可复查。

## 帧率口径（先看这条）

**VMD 的帧号以 30fps 为基准。** 默认渲染 30fps 时，一帧 VMD 对一帧画面，动作按作者编排的速度播放。

改 `fps` **不会重采样**，只会整体改变播放速度（时长 = 帧数 / fps）：

| 帧数 | @30fps | @24fps |
|---|---|---|
| 833 | 27.77 s | 34.71 s（慢 25%） |

所以 24fps 不是"换个帧率"，是把动作放慢四分之一。真要 24fps 得先重采样（插值生成新关键帧），那是另一个功能且必然有损。

非 30fps 时 `S3_motion` 会给出 WARN 并附两种 fps 下的时长对照。

## 两条必须知道的结论

**一、相机必须冻结，不能每次测。**

全片包围盒由裙摆/头发刚体的横向摆动决定，而 270 刚体 + 339 弹簧约束这套系统逐次重算会分叉。实测同一个 `.blend` 两个进程测出 X = 1.005 / 1.159，相机偏 19–40 px。而渲同一帧两次是**逐像素相同**的。

所以：测一次 → 写进 `camera.json` / 预设 → 之后一律复用。顺手省掉 100 秒预演。

**二、物理的位级一致性做不到，误差约 0.18%。**

实测（全部在同一个 `.blend`、同样的相机、同样的操作序列下）：

| 对比 | 平均差 | 最差帧 |
|---|---|---|
| 新管线 vs 原工程成片 | 0.436 / 255 | 1.56 |
| 管线跑两次 | 0.456 / 255 | 1.42 |
| 纯步进不渲染，仅第 180 帧 | **0.000** | 完全相同 |
| 纯步进不渲染，第 360 帧 | 0.512 / 255 | — |

第 180 帧还逐像素相同，到 360 帧就散开——**误差随帧数累积放大**。根因是 Blender 刚体求解器跨进程不保证位级一致（270 刚体 / 339 弹簧，只要一次接触解算顺序不同就会被放大），不是流程缺陷。

已经排除的假设：进程隔离、删掉多余预演、渲前重新加载 `.blend`——都试过，残余抖动不变。

所以「稳定复现」的实际含义是：

- **完全一致**：动作、骨骼位置、材质、相机、构图、帧数、时长、帧编号
- **0.18% 抖动**：裙摆与头发的褶皱细节（肉眼不可辨）

要位级一致，唯一路径是**烘焙缓存后渲**（渲缓存是确定的）。代价约 +0.25 s/帧，且 300+ 刚体的烘焙/无头存盘有段错误风险（未验证）。

## 物理资格判断器

默认让全部刚体参与物理解算，会把「在 PMX 里被焊死」的部位变成一块僵在 A-Pose 上的硬板。
判断器负责在渲染前决定哪些部位不该做物理，**判据全部来自关节数值与图结构，不看任何名字**
（卡芙卡叫 `HairA1_JNT`，飞霄叫中文，靠名字换模型必漏）。

三步：判断 → 匹配 → 修理。

| 档 | 判据（全部结构量） | 处置 |
|---|---|---|
| 焊死 | 该刚体参与的**所有**关节都是「限位全 0 且 弹簧全 0」 | mode1/2 静音其骨的 COPY_*；mode0 只作碰撞体，不动 |
| 僵死嫌疑 | 单元内**无 mode2** + 焊占比 ≥40% + 有闭环 + ≥3 体 | 报 WARN 并列证据，`--physics-policy strict` 才动手 |
| 跟随碰撞体 | 无关节 + mode0 | 实测跟随骨骼（f60 与骨差 2 mm），正常，不动 |

四模型实测：

| 模型 | 物理 | 焊死(需修) | 僵死嫌疑 | 跟随碰撞体 |
|---|---|---|---|---|
| 飞霄 | 261 | 8（耳） | 0 | 43 |
| 绯英 | 218 | 15（耳） | 0 | 34 |
| 赛飞儿 | 178 | 19（兜帽/耳/尾） | 0 | 38 |
| 卡芙卡 | 128 | 0 | **2（左右ひじ袖）** | 15 |

卡芙卡那两只袖子是 25 体 / 48 关节 / 环 24 / 焊占比 50%。`strict` 自动静音 **48 根骨、48 个约束、0 遗漏**，
与工程报告里手工做的「静音袖骨上的 48 个 COPY_TRANSFORMS」逐数一致。

**自动修复 vs 手工修复（480 帧逐帧 A/B，同一相机）**

| 对比 | 平均差 | PSNR 均值/最低 | SSIM 均值/最低 | 结论 |
|---|---|---|---|---|
| vs 原工程 **v2**（袖子刚性 + 头发物理） | 0.0017 / 255 | 71.82 / 69.34 dB | 0.999990 / 0.999983 | **等价** |
| vs v3（+ PMX 头发外移 4.8 mm） | 0.0358 | 53.35 / 38.40 | 0.998674 / 0.978724 | 差在 PMX 修复 |
| vs v4（+ 头发也刚性） | 0.1627 | 39.17 / 32.75 | 0.981685 / 0.929080 | 差在头发 |

v2 那次最差帧只有 **2 个像素**差超过 8。v4 的差异 0% 落在下半身、集中在头部与中段——就是头发。


```bash
--physics-policy report   # 默认，只报告
--physics-policy welded   # 静音全焊死（耳、兜帽）
--physics-policy strict   # 再加僵死嫌疑（袖子那类）
```

## 净空修复（初始穿透）

导入前把「从一开始就埋在头里」的头发/装饰外移，并同步关节锚点。

- 检测：胶囊/球两两对，**双向掩码 bit=1 + 非关节连 + mode1/2** 三重过滤
- 排除：mode0 纯碰撞体堆叠（`首` 的胶囊插进头里是正常设计）、头部胶囊彼此互叠（模型自带）
- 修复：沿真实线段最近点方向外移 `侵入 + margin`，逐轮收敛
- 写回：**只改位置浮点数**，原文件其余字节原样保留（不重序列化）

```bash
--clearance                 # 开关
--clearance-margin 0.06     # PMX 单位，0.06 ≈ 4.8 mm
```

卡芙卡实测：

| 项 | 结果 |
|---|---|
| 检出 | HairH3 +7.17 / HairC3 +5.93 / HairD2 +3.21 mm（报告 §2.2：7.2 / 5.9 / 3.2） |
| 修复 | 动 3 个刚体、同步 3 个关节、3 轮收敛 |
| 验证 | **C1–C8 全过**（多动 0 / 漏动 0 / 残留 0 / 最紧余量 0.12 mm / 失配 0.0000 / 新增重叠 0） |
| 复现 | 与手工 `卡芙卡3.0_fixH.pmx` **位置 0 差异**（对方文件被重序列化，长 1620 字节） |

## 门禁

`G1` 刚体>0 · `G2` 约束链 ≥0.8×刚体 · `G3` 动作>100 曲线 · `G4` 首帧≠中帧 · `G5` 探针刚体每 10 帧位移>5 mm · `G6` 非黑片 · `G7` 取景在框内 · `G8` 帧数连续+时长吻合

任一 `block` 立即停，不带着错误往下渲。

两条实现细节，都是被真模型打出来的：

- **G5 不依赖命名**：先按 裙/下擺/スカート/hair 找，找不到就自动选「相对髋部 10 帧位移最大」的刚体当探针。卡芙卡的刚体全叫 `HairA1_JNT`，靠模式表永远认不出。
- **G7 不只看刚体**：取「网格求值包围盒 + 骨骼 + 刚体」的并集。卡芙卡 145 个刚体只覆盖 1.258 m，实际身高 1.758 m，只算刚体会按矮个子取景，脚下贴边。
