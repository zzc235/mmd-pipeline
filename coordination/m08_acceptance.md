## 2. 交付物：`.blend` 必须自洽

2026-11-16 已证实的缺陷：`out/subai/M02/blend/B_from_blend1.blend`（= `E_base` = `G_base`，sha `dd7f6877…`）缓存 `is_baked=true` **且 `is_outdated=true`**，**打开即渲染**得到回放轨迹，与解烘焙重算的轨迹差**下摆 0.9087 m / 全刚体 1.6206 m**——同一个文件给出两条动画（D-044）。

验收要求：

- 交付的每个 `.blend` 必须通过 `m02_cache_gate.py` 的 `exit 0`，即满足二者之一：
  - `is_baked = false`（首次 `frame_set` 会重算，handoff 必须写明耗时）；
  - `is_baked = true && is_outdated = false`（回放 == 重算）。
- `exit 3`（`DEFECT_BAKED_OUTDATED`）一律判不通过，不许以"能渲染出片"绕过。

## 3. 场景构成必须写进验收结论

交付场景 `B_from_blend1.blend`：**一具模型骨架 + 一具 mmd_tools 物理 rig**（不是两个角色）。

| armature | 骨数 | 裙摆骨 | `下擺_0_*` | `下擺_11_*` | 子对象 |
|---|---:|---:|---:|---:|---:|
| `星穹铁道—飞霄（无外套）_arm` | 482 | 166 | 18 | 11 | 61 |
| `星穹铁道—飞霄（无外套）_arm_rig`（物理 rig） | 737 | 0 | 0 | 0 | 0 |

540 个 mesh / 324 个刚体全部归 `_arm`。其中 **11 个刚体对象名为未替换的模板变量 `$name_j`**，绑定在同骨架第 11 行的 `下擺_11_7…11_17` 上——这些骨在源 PMX 里**存在但无刚体**，刚体是本流水线补出来的（`kinematic=True`、`type=0`、碰撞掩码只 bit0）。

**这不是无害的补件**：`P0 vs P10`（只关这 11 个静态体的碰撞）下摆位移 **5.715 mm**，即**我们自己补的占位刚体在改变交付动画**。因此：

- 交付说明必须写明这 11 个刚体的存在、作用与命名问题（`$name_j`），否则等于隐藏了一次动画变更；
- 要么给它们正规命名并写进交付说明，要么移除后重测——两条路都要在 M08 前定案；
- 禁止用 S8 支撑"裙摆与身体之间的碰撞有效"这一表述（S8 的分层见 §5 与 `D-055`）；
- **骨↔刚体归属只认「骨 → 骨架」**：`obj.parent` 不可靠（324 个里 265 个的父是 Empty `rigidbodies`，走父链只认对 59 个），对象名也不可靠（形如 `035_右胸`）。

## 5. 数字的引用规则

- 任何数字必须注明**在哪个 HEAD / 哪个 commit 上量的**；提交前量的数不算。
- 任何"改一个量 → 看轨迹有没有变"的实验，`point_cache` 状态必须先落证据；`is_baked=true` 的输入不得作为 A/B 实证（D-040）。
- 混沌解算器上「`D ≥ 阈值`」只能判**参数接没接上**，判不了**影响多大**（D-043）。
- 测量类提交，**自检结果与该笔数字同笔提交**，自检不得晚于数字（D-041）。自检不过时，那一笔的正确形态是 `RETRACTION`。
- 引用他人数据时标明出处与前提（例："输入为回放轨迹（`is_outdated=true`）"）。
