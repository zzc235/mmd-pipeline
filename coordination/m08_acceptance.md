## 2. 交付物：`.blend` 必须自洽，且自洽由**行为探针**证明

2026-11-16 已证实的缺陷：`out/subai/M02/blend/B_from_blend1.blend`（= `E_base` = `G_base`，sha `dd7f6877…`）缓存 `is_baked=true` **且 `is_outdated=true`**，**打开即渲染**得到回放轨迹，与解烘焙重算的轨迹差**下摆 0.9087 m / 全刚体 1.6206 m**——同一个文件给出两条动画（D-044）。

**同一天晚些时候的重要更正**（D-067）：**标志位判不出好坏**。一次健康的烘焙件（`bake_all` 后 326 帧）重开同样显示 `is_baked=true && is_outdated=true`，但它的冷跳 f109/f240 与顺序重算**逐位相同**。`is_baked && is_outdated` 的真实含义是「打开时无法证明缓存与当前设置一致」，它只是**筛选信号**。

验收要求：

- 交付形态取 **B（烘焙）**：`ptcache.bake_all(bake=True)` 实测可用（32.2 s / 326 帧 / 无段错误 / 不要求 `use_disk_cache`），代价 33 s/场景、+650 KB。§6 的豁免为常驻，条件四条：只在副本上、每场景单次、崩溃只记退出码不重试、**成功也必须过行为探针**。
- **行为探针 = 冷跳中间帧 vs 顺序重算**：两者逐位相同 → `OK_BAKED_VERIFIED`(0)；不一致 → `DEFECT_BAKED_OUTDATED`(3)；**没做探针 → `SUSPECT_BAKED_OUTDATED`(4)，未测 ≠ 不合格，不得静默放行**。
- 不烘焙交付（A 路）只作降级：必须写明「从 `scene.frame_start` 顺序求值」，且**已知对人不成立**（谁拖时间轴谁看到别的动画）。

## 4.5 产物与回归的可比性（2026-11-16 实测）

- **产物字节不可复现**：同一入口跑两次，PNG 清单摘要 `f05f2d94…` vs `2a8dbff6…`，mp4 27600 vs 27675 B。⇒ 回归只比**阶段序列 / `[PASS]` 集合 / 帧数 / `720×576` / `30-1` / `0.4 s` / `S8_verify` 结论**，不比字节。
- **E 与 F 不能共用临时仓库**：隔离用 `BLENDER_USER_EXTENSIONS` + `install-file --no-prefs`（不带 `-e`）；同一 `user_default` 仓库里隔离会让 `mmd_tools` 一起消失，F 段随之失败。`--factory-startup` **不管**扩展目录。

## 5. 数字的引用规则

- 任何数字必须注明**在哪个 HEAD / 哪个 commit 上量的**；提交前量的数不算。
- 任何"改一个量 → 看轨迹有没有变"的实验，`point_cache` 状态必须先落证据；`is_baked=true` 的输入不得作为 A/B 实证（D-040）。
- 混沌解算器上「`D ≥ 阈值`」只能判**参数接没接上**，判不了**影响多大**（D-043）。
- 测量类提交，**自检结果与该笔数字同笔提交**，自检不得晚于数字（D-041）。自检不过时，那一笔的正确形态是 `RETRACTION`。
- 引用他人数据时标明出处与前提（例："输入为回放轨迹（`is_outdated=true`）"）。
- **网格穿透数字必须四样同笔**：可计分样本数 / 不可计分比例 / 合成实体三项自检读数 / `target_has_skirt_polys`。只报一个深度数字的证据直接退回；**不许靠收紧筛子把真实网格凑到 95%**——95%/5 mm 只用于解析实体自检（量方法对不对），不量产率（`D-074`）。
- **每条证据必须能被 `coordination.evidence.digest()` 原地复现**，且**文件 sha256 == hexdigest**；`interface` 只能是版本串，结构化内容进 `measurements`（`D-072`/`D-080`/`D-082`）。
- **合并前测试必须跑两种环境**：默认环境与 `PYTHONIOENCODING=utf-8`；凡被测试用子进程调用的 CLI，还要有一条「子进程 GBK 环境、父进程 UTF-8 解码仍成功」的测试（`D-076`/`D-081`）。
- **扫描器类校验必须报「扫了多少、跳过多少」**：`scanned` 有下限、`skipped` 为空或逐条列出，否则「0 命中」与「一个都没扫」同形（`D-086`）。
- **依赖未落地规范的校验必须报 `PENDING`，不许报 `FAIL`**：先探「这条规则在不在」（例：`normalize()` 收不收某个键），不在就 `PENDING`（不喊狼），在了才判 `PASS/FAIL`（`D-091`）。理由：`FAIL` 与 `PENDING` 混同会让下一个人去修一个不存在的缺陷，把没测当失败又会掩盖真问题。
- **预演值换内容时，旧值必须标作废并与新值写在同一处**，否则它会以「缺陷」的形状回来（`D-091`：`c1fe8be2…` → `b837f933…`）。
- **验证者的输入本身是证据的一部分**：用哪个 commit 的模块、哪种编码、哪种口径，都要写出来；能独立复算的复算，只能自证的标明是自证。
- **每个「相等/没变」的结论要配一个人为改造的对照**：证明这把尺子看得见差异。`D-093` 是范例——同一份烘焙件上只改一个 `kinematic` 标志，逐帧最大位移 1.692274 m，所以「`bake_all` 后冷跳与 `P0` 逐位相同」才不是「回放本身看不出差别」。同理，`P9`（应当被拒）与 `D`（应当通过）共用同一条 `REQUIRE_CHANGE` 判据，一拒一过才证明拒绝不是脚本空跑。
- **被吞掉的异常都长得像「干净」**（`D-101`）：凡是 `except` 分支，被吞掉的那一份必须进入某个可打印的计数；凡是有计数的，`0` 与「没扫/没读到」必须能被区分（要么显式 `read_failures`，要么 `scanned==0` 直接不可判绿）。今天四个实例：BOM 假阴性、`scope` 测错层、`scanned=0` 假绿、`int(mask)` 吞 `TypeError` 使「不该互撞的对」算成 0。
- **`PENDING` 的有效期只到规则落地那一刻**（`D-092`）：通道/规范落地后，同一探头的 `UNWIRED` 必须从 PENDING 降级为 FAIL，否则同一个退出码在两个时间段里意思不同。
- **讨喜的数字要先自证**（`D-102`）：凡是给出「0 / 没有影响 / 全部正常」的结论，必须附带一个能证明「这个 0 不是因为没对上」的正控（例：2号 的 `unresolved=0` 才允许解释那 36 对）。今天三次同族：`scanned==0` 不可判绿、`disallowed_pairs=0` 不能读成「PMX 没有这种对」、join 键对不上导致 `0% 受影响`。**不讨喜的数字反而通常算对了。**
- **按枚举取值筛选之前，先断言这个取值真的在枚举里**（`D-117`）：1号 用 `rbc.type == "DISABLE_COLLISIONS"` 数约束，而 Blender 的枚举里没有这个类型 ⇒ 筛选恒空、输出恒 0，读起来像「场景里没有这种约束」。实测场景里有约 4009 条（布尔 `disable_collisions`）。**谓词本身不成立**比吞异常更隐蔽：它不抛错、不报警，只是永远返回空。
